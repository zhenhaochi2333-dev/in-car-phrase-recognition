首次运行发现第三方关键词引擎不能打开中文工作区路径中的关键词文件，已通过当前用户目录下的英文运行缓存路径修复。原课程资料和项目模型源文件没有移动。

两个识别引擎已成功加载运行；C++ 实验核心执行了静音输入的基础运行检查。自定义模式完成真人短语识别与合成播报，用户反馈实时性和准确性良好，并确认可以播放识别结果。此前联调日志 `exports/hardware-20260910-120406.jsonl` 中记录了“打开空调”“播放音乐”的 command 事件，以及相应的播报开始、播报结束和收音抑制状态。

## 当前交互：停止后编辑

此前定位到按钮无法操作是监听时整体禁用了编辑区，并曾实现监听中编辑。用户实际体验后明确选择恢复为“停止监听后修改”，当前实现以此为准。

修复后的行为：

- 监听、模型加载、播报及等待停止期间锁定短语库和设置；提示先在工作台点击停止。
- 两个工作线程都退出后解除锁定；保存前校验短语和词元，重复或无效发音留在弹窗内提示。
- 保存配置不会启动监听或播放声音；由用户再次点击开始监听。保留会话记录和自动播报选择。
- 模式、设备、识别参数、播报音量和语速在停止后修改；自动播报开关仍可随时关闭。
- 空启用列表允许保存，但不能启动自定义监听。
- 新增或编辑后清除搜索过滤并选中修改项，避免保存成功却看不到新短语。

## 复现

普通交互回归不打开音频设备：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_ui_interactions.py -v
```

真实麦克风回归需显式启用，测试结束后释放设备：

```powershell
$env:PHRASE_LAB_REAL_MICROPHONE = '1'
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_microphone_update.py -v
Remove-Item Env:PHRASE_LAB_REAL_MICROPHONE
```

真人联调入口，使用已保存的模式打开界面并直接监听，不自动播放合成测试口令；当前默认模式为实验口令：

```powershell
.\.venv\Scripts\python.exe scripts/verify_live.py --device 2 --manual --page phrases
```

设备索引随 Windows 设备列表变化，运行前应核对。验证日志只记录识别文字和任务事件，不保存原始录音。

可追加 `--mode custom` 或 `--mode experiment` 显式切换模式。默认短语库现为实验要求的十个英文口令；前文中文联调与交互回归使用各自的中文短语配置，不代表英文实验模型的准确率已经测定。
